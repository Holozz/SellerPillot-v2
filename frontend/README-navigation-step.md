# 本步：工作区导航

将包内 src 合并到 D:\Project\SellerPilot\frontend\src，仅包含三个代码文件：

- App.tsx：把五个并排挂载的业务组件，替换为一个 StoreWorkspace。
- StoreWorkspace.tsx：新增导航和模块显示管理。
- workspace.css：新增导航样式，沿用现有字体和颜色。

其余业务组件、api.ts 和后端均无需修改，也无需安装依赖。前端端口仍是 5188。

## 验收

1. 选择店铺，应看到五个入口：运营问答、经营数据、商品与库存、CSV 导入、标题审核。默认打开运营问答，每次只显示一个模块。
2. 向 Agent 提问，收到回答后切到商品库存，再切回来。已完成的聊天和未发送的输入应保留，追问继续使用当前对话。
3. 在标题审核生成草稿、勾选核对，切到别的模块再返回。草稿与勾选应保留，切换本身不会确认应用标题。
4. 在 CSV 导入选择文件，切到经营数据再返回，文件选择应保留。文件只有点击上传按钮才发送。
5. 查询经营数据，切到别的模块再回来，日期、状态和结果应保留。
6. 可以在聊天或导入等待期间切模块，同店铺请求继续处理，返回原模块后查看结果。
7. 换店铺后默认回到运营问答，旧聊天、草稿和文件选择必须消失。再切回原店铺，也不会恢复刚才的旧工作区。

模块保留的是当前页面内存里的状态，浏览器刷新会重建页面。后端已保存的数据不会因为页面重置而被删除；历史聊天与草稿列表的恢复不在本步范围内。

## 新组件 StoreWorkspace

App 负责登录身份和店铺选择，StoreWorkspace 负责当前店铺的模块导航；五个已有业务组件继续负责各自的请求和操作。

Props 接收 store 和 onSessionExpired，分别传递给业务组件。任意已打开模块收到 401，仍会通知 App 清除登录状态。

PanelId 是字符串联合类型，限制模块编号只能是 chat、operations、inventory、imports、titles。PANELS 数组保存编号与显示名称，map 将它变成五个导航按钮。

activePanel 保存当前显示的模块，初始为 chat。visited 保存当前店铺已经打开过的模块，初始只有 chat。首次进入工作区不会触发商品或标题模块的加载请求。

## handleNavigate(panelId)

导航按钮点击时调用这个函数。

1. setActivePanel(panelId) 选择要显示的模块。
2. setVisited 使用函数式更新，current 是 React 提供的最新已访问列表。不能只依赖事件函数捕获的旧 visited，否则快速连续操作时可能遗漏更新。
3. includes 判断是否已访问。访问过就直接返回原数组，不重复添加。
4. 未访问则用 [...current, panelId] 创建一个新数组，在已有列表后加入模块编号。这里不使用 push，避免直接修改 React 原来的状态对象。

这两个状态各有职责：activePanel 决定显示谁，visited 决定哪些模块已经创建。一个模块可以已创建但暂时不可见。

## 为什么保留组件，再用 hidden 隐藏

visited.includes(...) && <业务组件 /> 决定模块是否创建。模块一旦访问过，这个条件在当前店铺中始终为 true。

外层容器的 hidden={activePanel !== '...'} 决定是否显示。hidden 隐藏内容及其中的控件，但不会卸载 React 组件，所以聊天、草稿、原生文件输入框和请求控制器都保留下来。

如果只写 activePanel === 'chat' && <AgentChat />，切走时 AgentChat 会被卸载。它的 useState 会丢失，清理函数也会取消等待，切回来就不是之前的聊天状态。

导航按钮用 aria-pressed 表达当前选中状态，用 aria-controls 指向固定容器 ID。按钮本身可通过 Tab 聚焦，Enter 或空格激活。这里使用普通导航按钮，没有额外实现带方向键约定的 ARIA 标签页。

## 为什么换店铺仍然会重置

App 把 `${user.id}:${selectedStore.id}` 作为 StoreWorkspace 的 key。账号或店铺发生变化时，React 将其视为另一个工作区，卸载旧工作区及其所有子组件，再创建新工作区。

因此“切模块”只是显示变化，“换店铺”会重建组件。各业务组件已有的清理函数负责取消浏览器等待并忽略旧响应。取消等待不等于撤销后端已收到的导入或标题确认，仍可按已有机制重试或查询操作状态。

## 数据刷新边界

模块切换不会重新请求已打开模块的数据。导入订单后，需要在经营数据页点击查询；应用标题后，需要在库存页点击查询读取当前标题。

本步仅管理页面内导航，没有新增 URL 路由、浏览器历史导航或长期状态存储。
